# Patterns

Two kinds of patterns live here: **invariants** (non-obvious facts about runtime
behavior — the things that bite you if you don't know them) and **recurring code
patterns** (the shapes the codebase consistently uses — copy them, don't invent
new ones).

## Invariants

- `WithOutputs` stashes live `Output`s in `Config.resolvedOutputs` and `buildOutputs` short-circuits on them. It also mirrors `Type`/`Format`/`Path` into `Config.Outputs` for validation via type assertions — when adding a new `Output` implementation, update both the resolved-output path and the metadata mirror in `options.go`. The first `WithOutputs` empties `Config.Outputs` before mirroring, so outputs loaded from a file are neither opened nor validated: options override the file.
- Only the root `Logger` (the one from `New`) owns the engine and outputs. `Named` and `With` return forks that mark `isFork = true`; calling `Close` on a fork returns `ErrLoggerNotRoot` and leaves resources untouched. Do not add resource ownership semantics to forks.
- A file output belongs to one `Logger` or `Event`: `New` and `NewEvent` claim every `*fileOutput` through `openOutputs` (`fileOutput.claim`), all or none, so the same `Output` value given to a second one fails with `ErrOutputInUse`, and a closed one with `ErrOutputClosed`. Sharing a file is done by path, which the rotator registry makes safe. A build that fails after the outputs goes through `abandonOutputs`: it closes the outputs built from `Config.Outputs` and unclaims the ones given to `WithOutputs`, which the caller still holds. `WithAgentMode` claims an output before closing it, so it never closes one that belongs to another. A new constructor that takes outputs claims them the same way, or two owners close one file under each other.
- `cloneAnnotations` is called by `Named`, `log()`, and `Event.Emit` to break shared backing-array aliasing. Any new code path that forks a logger or hands an annotation slice to hooks must clone first — otherwise hook mutations (e.g. PII masking) leak across siblings, or into the slice a caller passed to a level method with `...` — and expand `Annotable` values with `expandAnnotable` before the hooks run: an `Annotable` the PII hook receives whole is masked as one struct, and one expanded only at serialization is never masked at all.
- Every caller field is written under `logline.FieldKey` of its name (`annotationsToFields`): an annotation named like a key axio writes gets a leading underscore, so no line carries a key twice and `axio render` never takes a caller's field for axio's. A new key axio writes goes into `FieldKey`'s list, or the collision comes back.
- Every engine wraps its core in `reportingCore` (`buildEngine`, `buildEventEngine`), which reports a failed write on stderr as one `axio:` line and hides the error from zap. A new engine that skips the wrapper brings back zap's own error format.
- `Logger.Close` is idempotent on the root: a second call returns `ErrLoggerClosed`, and `log()` becomes a silent no-op after close (no panic). The `closed *atomic.Bool` is shared with forks so the no-op covers them too. `Event.Close` follows the same shape with `ErrEventClosed`, and takes the event's mutex so an `Emit` already writing finishes before the outputs close; an `Emit` after `Close` is a silent no-op. A file output closed twice returns `ErrOutputClosed`.
- An audited Logger or Event writes through `auditCore` (`audit.go:442`): it encodes the entry once as JSON, and `HashChain.appendAndWrite` (`audit.go:180`) hashes those bytes, persists the chain and writes every output while holding the chain's mutex. Keep the writes inside that call: the file's order is the chain's order only because nothing is written after the lock is released. A core is handed fields and never a context, so an audited Logger or Event appends `contextField(ctx)` — a Skip field every encoder writes nothing for — and `auditCore` counts the record against that context. A new path that writes through an audited core appends it too, or its records are counted against `context.Background`.
- `WithAudit(path)` resolves to one `HashChain` per absolute path through `chainsByPath` (`audit.go:631`), so a Logger and any number of Events on the same path extend one chain. It is one of the two deliberate pieces of package-level state, the other being `filesByPath`, and for the same reason: two chains loaded from the same store would each start from its last hash and fork it. Across processes the store itself is claimed: `FileStore.claim` takes an exclusive flock on `<path>.lock` at the first `Save` and keeps it for the life of the process, and `sharedChain` claims before loading, so a second process fails in `New` with `ErrChainStoreLocked`. A chain given through `WithAuditChain` over a `FileStore` is claimed in `New` too (`HashChain.claimStore`, through the `storeClaimer` capability), and reloaded after the claim under the chain's mutex, since it was loaded before anything held the store. `Load` never locks — that is what lets `axio verify` read a store in use. Windows, Solaris and AIX have no flock (`storelock_other.go`).
- Every log file this process has open is an entry of `filesByPath` (`rotator.go`), keyed by its absolute path with the symlinks resolved (`canonicalPath`), so a relative path, an absolute one and one through a symlinked directory reach the same entry. The key is looked up as given first, and only a path not registered as it is gets opened and resolved, all under the registry's mutex. The resolution comes from the name, never from the open descriptor: a rotator may move the file aside between the open and the lookup, and a descriptor then names the backup, which would key a second rotator on it. On Linux the descriptor's path from `/proc/self/fd` only confirms that the path given is already the resolved one; when it is not, `filepath.EvalSymlinks` resolves it and the file is opened again at the key. A sequential `NewEvent` on a rotating file opens and releases it every time, so that path is held to the cost it had over lumberjack (`BenchmarkNewEvent_RotatingFile`): the log and its lock open through `openLogFile`, which skips the runtime poller on Unix, the size comes from a seek and the lock's time is read only with `Interval`. A change that adds a call or an allocation there shows in that benchmark. A `RotatingFile` shares the entry's one `rotator`, which renames, reopens and locks the resolved path, so a log that is a symlink stays one and its target rotates; a `File` only counts on its entry, so the two on one path fail with `ErrRotationConflict`, as does another `RotationConfig` while the path is open. Two rotators of one file would each rename it under the other and lose lines, which is why the registry exists. References live in the entry, under the registry's mutex; the lock order is always the registry's mutex, then the rotator's, and a rotation, which runs under the rotator's mutex, never touches the registry. The last reference closes the log, releases the lock on `<path>.lock` and removes the entry, so nothing stays in memory, open or running once no output uses a file; a cleanup of the backups that is still running counts as a reference for the lock and the entry, and ends them itself (`finishCleanup`). A request that conflicts with an entry only such a cleanup holds — another rotation, or a `File` — waits on the channel the cleanup closes when it ends (`cleanupDone`), then registers anew, rather than failing with `ErrRotationConflict` for a file nothing uses. The interval of `Interval` survives that: it starts at the modification time of the lock, which every rotation and every empty-file restart touches. Across processes the rotator takes `lockExclusive` on the lock, so a second process fails with `ErrRotatingFileLocked`; Windows, Solaris and AIX have no flock.
- An audited Logger needs a JSON output (`validateAuditOutputs`, run by `New` and not by `Config.Validate`): only JSON lines carry the hashes. An Event writes JSON to every output, so the same `Config` stays valid for an audited Event.
- PII masking is on unless `Config.PIIDisabled` is set: `buildHooks` builds the `PIIHook` for every other `Config`. The switch is named for turning the protection off because its zero value has to be the secure one — `LoadConfigFrom` starts from a zero `Config`, and so does a literal, so a `PIIEnabled` would leave either of them unmasked. A new switch over a protection takes the same shape; `WithPII` sets `PIIDisabled` back to false, as options override the file.
- A value zap has no encoding for — a struct, a slice, a map — is written by axio's own encoder: every config in `internal/logline/encoder.go` sets `NewReflectedEncoder` to `newValueEncoder`, which encodes with `encoding/json/v2` under `logline.ValueOptions`, and PII masking encodes with the same options (`jsonTree` in `pii.go`). That is the only reason the tree the mask inspects is the one the log writes: a config that leaves the field nil falls back to zap's `encoding/json` v1, and a value the mask found clean is then written in a form it never saw. A new encoding option goes into `ValueOptions`, never into one side alone; a marshaler only one side needs — the mask's redaction of binary bytes — is passed through `ValueOptions(marshalers...)`, which keeps axio's own.
- A built-in pattern for a number (`piiPatternInfo.numeric`: CPF, CNPJ, card, both phones) reads the text through `numberText`, in `maskPatterns` and `binaryCarriesPII` alike. `separateLabels` turns the letters and `_` of a token that glues digits to a label into `#`, so `cpf12345678901` is a number to `\b`; a token of hex digits with a letter among them is an identifier and is read as it is, which keeps trace ids and hashes out. Its matches then come from `uuidText.matches`, which never matches inside a whole UUID — 8-4-4-4-12 hex with no hex digit beside it, carrying an RFC 9562 version and variant or being the nil UUID (`isWholeUUID`) — keeping those found in a copy with the UUIDs' digits turned into `x` at the same indices, and those that cross a UUID's border, since PII glued to an identifier is still PII. Every copy keeps the length of the text, so a match in it is replaced in the text at the same indices. The e-mail and custom patterns read the text as it is. The digits are hidden rather than the matches filtered afterwards because a match dropped after the fact still consumed the text an overlapping one needed; the gap that remains — a match starting inside a UUID and running past it, behind a match inside it — is the exception named on `uuidText.matches`. A new path that runs the built-in patterns for a number goes through `numberText` too, or a label hides a CPF and an identifier is masked as a card again.
- The text format has two writers that must agree: the Console, and `logline.Renderer` rendering JSON back into text for `axio render`. Service metadata reaches only JSON (attached to JSON cores and to the audited core's canonical encoder, never to text encoders) and the text hash is `logline.ShortHash`; the renderer drops and shortens the same keys. A field value it can show only as JSON holds it: a `time.Duration` or `time.Time` annotation, which the Console writes in text form, renders as its JSON value — JSON does not carry the type. `TestRenderer_MatchesConsole` compares the two byte for byte — a change to either side that the test does not cover is a divergence waiting to happen.

## Recurring code patterns

- **Functional options.** New configuration entry points are `func WithX(...) Option` closures that mutate `*Config`. See `options.go:54` (`WithOutputs`), `:93` (`WithAgentMode`), `:130` (`WithHooks`), `:155` (`WithPII`), `:175` (`WithPIIDisabled`), `:193` (`WithPIIMaxDepth`), `:214` (`WithPIIOmitErrorVerbose`), `:229` (`WithOmitCaller`), `:255` (`WithAudit`), `:281` (`WithAuditChain`), `:308` (`WithMetrics`), `:339` (`WithTracer`). Don't add public setters, build-time flags, or package-level state — extend `Option` instead.

- **Sentinel errors grouped by concern.** `errors.go` defines `var (...)` blocks per concern (validation, building, outputs, audit, metrics and tracing, lifecycle). New error cases declare a sentinel and wrap at the call site with `fmt.Errorf("%w: %w", ErrX, err)` so callers can `errors.Is`. Don't inline `errors.New(...)` at the call site.

- **Optional capabilities via type assertion.** Hook features that not every hook needs are expressed as marker interfaces (e.g. `MetricsAware` at `hook.go:79`) and detected via `aware, ok := hook.(MetricsAware)` at `hook.go:120` and `:137`. Don't widen the base `Hook` interface to absorb optional behavior — add a new marker interface and assert.

- **Fixed hook chain ordering.** The internal `hookChain` runs hooks in a deliberate order — PII → custom — documented at `hook.go:84-98` and enforced by the append order in `buildHooks` (`hook.go:209`); a `PIIHook` passed through `WithHooks` is a custom hook and runs in the order passed. Auditing is not a hook: it hashes the line at write time, after the whole chain, so PII is masked before hashing and the hash covers what custom hooks changed. Any new hook must slot in at the right position, not be appended unconditionally.

- **`Validate()` chain.** Enum types each carry a `Validate() error` (`axio.go:214` `Environment`, `:254` `Level`, `:283` `Format`), and `Config.Validate` (`config.go:279`) composes them; `New` and `NewEvent` wrap its error with `ErrValidateConfig`. New enum-like types or config fields follow the same shape rather than scattering ad-hoc checks at construction.
