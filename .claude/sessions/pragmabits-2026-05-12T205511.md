## 2. Work Completed

### 2.1 First batch — items #9–#13

**Problem:** Five user-flagged pre-release findings.

**Solution:**
- **#9** `Event.Close` rewritten to collect per-output errors into `[]error` and return `fmt.Errorf("close event: %w", errors.Join(errs...))`, mirroring `logger.Close` at logger.go:368-383. Same wrap-prefix shape.
- **#10** Time-rotation goroutine in `fileOutput` now stores the most recent `lumberjack.Rotate()` outcome in `lastRotationError atomic.Pointer[error]` and exposes it via `LastRotationError() error` on a public `RotationErrorReporter` marker interface (matches `MetricsAware` pattern at hook.go:77 documented in `.claude/rules/patterns.md`). Successful rotations clear the stored error.
- **#11** `Annotation.Set(any)` deleted along with its `toField` helper. PII masking converted to slice replacement (`fields[i] = Annotate(fields[i].Name(), newValue)`) at pii.go:275, 281, 336, 343. Same wire format as Pino / OTel / slog.
- **#12** `HashChain.Verify` signature changed from `Verify([]ChainEntry, func(int) []byte)` to `Verify([]VerifiableEntry)` where `VerifiableEntry` is `{Entry ChainEntry; Data []byte}`. Caller no longer maintains an external index-aligned lookup.
- **#13** Locked decision: keep `gopkg.in/natefinch/lumberjack.v2 v2.2.1` pinned. No code change.

**Files:** event.go, output.go, rotation_test.go, annotation.go, annotation_test.go, review_followup_test.go, pii.go, audit.go, audit_test.go, benchmark_test.go.

### 2.2 Second batch — items #A–#E

**Problem:** Five additional issues surfaced during the post-first-batch code-review pass (after the user asked for "real problems").

**Solution:**
- **#A** `FileStore.Save` rewritten as atomic write: `OpenFile(stagingPath, O_WRONLY|O_CREATE|O_TRUNC, 0600)` → `Write` → `Sync` → `Close` → `Rename(stagingPath, s.path)`. All error paths remove the staging file. Delivers the visibility guarantee the `ChainStore` docstring promised but `os.WriteFile` did not. Variables named `stagingPath` / `stagingFile` (full words) per rules.md rule 7. Suffix `.staging` (full word). See decision row 9.
- **#B** subsumed by #A — the atomic rename eliminates the corrupt-on-disk path that the in-memory rollback at audit.go:153-159 could not recover from.
- **#C** `HashChain.computeHash` now calls `entry.Timestamp.UTC().Format(time.RFC3339Nano)` so `Verify` accepts entries whose timestamps were rehydrated in non-UTC zones. Backwards-compatible: `Add` already normalizes at write. Godoc on `ChainEntry.Timestamp`, `computeHash`, and `Verify` updated to document the contract.
- **#D** `Event.Emit` gains `emitted atomic.Bool` field and a `CompareAndSwap(false, true)` prelude before the mutex acquire. Documented "called once" contract is now actually enforced; double-emit is a silent no-op on second call. Test `TestEvent_Emit_Idempotent` uses memory-buffer output and asserts a single line on double-emit.
- **#E** PII map recursion + Annotable contract documented:
  - `DefaultPIIMaxDepth = 2` constant + `PIIConfig.MaxDepth int` field with zero-falls-back-to-default.
  - `PIIMasker.maxDepth int` resolved at constructor.
  - New `maskMap` and `maskMapWithCounts` helpers — fresh map allocation (no caller-side aliasing), depth-capped recursion.
  - `case map[string]any:` added to `MaskFields` and `MaskFieldsWithCounts` type switches.
  - Docstring at pii.go:260-273 (the false `Nested maps are processed recursively` line) rewritten to match actual behavior.
  - 6 new tests in pii_test.go (recursion, depth cap with default and override, no-aliasing, mixed value types, struct passthrough, zero-defaults).
  - 3 new benchmarks: `BenchmarkPIIMasker_MaskFields_NoMap` (~2.5 μs, 0 allocs/op), `_ShallowMap` (~2.8 μs, 12 allocs/op), `_DeepMap_AtCap` (~1.0 μs, 5 allocs/op).
  - `README.md` and `README.pt-BR.md` gain a "Coverage and Struct Annotations" / "Cobertura e Anotações com Struct" paragraph explicitly linking `Annotable` to PII-coverage for struct types.

**Files:** audit.go, audit_test.go, event.go, event_test.go, pii.go, pii_test.go, benchmark_test.go, README.md, README.pt-BR.md.
