### 2.5 Como o bumpit cria as tags de cada módulo (explicação)

**Problem:** o usuário perguntou como o bumpit sobe a tag dos módulos do projeto.
**Solution:** explicado a partir do código do bumpit v0.4.0:
- Acha os módulos: todo `go.mod` rastreado pelo git, menos `vendor`, `testdata` e diretórios que começam com `.` ou `_`.
- Escolhe o módulo: o raiz por padrão; outro com `--module`/`-g`.
- Prefixo da tag pelo diretório (`gomod.TagPrefix`): `v` na raiz, `cmd/axio/v` no comando.
- Versão atual: maior tag com o prefixo que já está no histórico do `HEAD`, por precedência SemVer.
- Commits contados: desde essa tag, só os do diretório do módulo, menos os módulos aninhados (`moduleScope.pathspecs`).
- Na série `0.y.z`, um breaking change vira minor (`Version.Next`).
- Antes de criar a tag, `verifyNext` confere que a versão é maior que a atual, que a tag não existe e que o module path aceita o major.
- Cria a tag com `git tag -a <tag> -m "Release <tag>"`, só localmente; quem assina é o git, por `tag.gpgsign=true`.
- O `explain` só lista os módulos do repositório que exigem uma versão anterior; não muda nenhum `go.mod`.
